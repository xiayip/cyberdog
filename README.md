# cyberdog

独立 ROS 2 Python 包，从现有 armie 提取控制适配和毛线球视觉实现，重写核心行为。
不依赖 armie；复用工作区的 ghost_game_orchestrator 轨迹/视觉伺服数学与
rebot_arm_hmi_bridge 控制器切换协议。不启动手势、人脸、舞蹈、VLM 或 HMI 节点。

## Docker 环境安装

依赖统一在 `scripts/setup_docker_env.sh`。适用于现有 **Ubuntu 24.04 / ROS Jazzy Zephyr GPU 镜像**，
工作区须已经构建底层驱动、相机和控制器。脚本安装缺失的 ROS/Python 系统包和 `pulseaudio-utils`，
创建复用系统 GPU 库的 `.cyberdog-yolo`，固定 `ultralytics==8.4.176`，检查 CUDA 算子、模型哈希、音频文件和桌面连接，最后只构建 `cyberdog`。
重复运行会跳过已安装依赖；不升级系统 PyTorch、torchvision、NumPy、OpenCV，不下载模型，也不启动机械臂。

在容器内以 `admin` 用户执行：

```bash
cd /workspaces/zephyr-dev/zephyr_ws
bash src/cyberdog/scripts/setup_docker_env.sh
```

也可以从本机宿主机执行：

```bash
docker exec -it --user admin zephyr_dev_24.04-aarch64-container \
  bash /workspaces/zephyr-dev/zephyr_ws/src/cyberdog/scripts/setup_docker_env.sh
```

首次连接宿主机音箱，或宿主机音频服务重启后，先在**宿主机已登录桌面的用户**下执行：

```bash
bash /home/xyp/code/zephyr_ws/src/cyberdog/scripts/setup_docker_env.sh --host-audio
```

此模式复用同目录的 `enable_desktop_audio.py`，只开启 `127.0.0.1:4713` 回环连接；
容器须使用 `--network host`，`audio_server` 默认已设为 `tcp:127.0.0.1:4713`。
暂时不连接音箱时可传 `--skip-audio-check`，但播放音频前还要接通音箱。

常用选项：`--check` 只检查；`--skip-build` 安装依赖但不构建；`--workspace /path/to/zephyr_ws` 指定其他工作区。
脚本只安装当前推理流程的依赖，不安装 YOLO 训练、导出或云平台扩展。
已验证的镜像 GPU 组合是 PyTorch `2.9.0+cu130`、torchvision `0.24.0`、NumPy `2.2.6`、OpenCV `4.13.0`；
这些由 Zephyr GPU 镜像提供。GPU 不可用时脚本会报错，应检查匹配硬件的镜像和 NVIDIA 运行时/GPU 透传。
底层 `mit_position_adapter_controller` 的接管补丁也须随工作区部署，不能仅安装本包代替。

验证：当前容器检查与构建通过；临时全新虚拟环境成功安装固定版本 YOLOE，实际 GPU 推理通过，
空白图未检出球；宿主机音频模式重复执行正常。检查没有启动 ROS 节点或执行机械臂运动。

## 使用

在开发容器中：

```bash
cd /workspaces/zephyr-dev/zephyr_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
colcon build --packages-select cyberdog --symlink-install
source install/setup.bash

```

启动驱动、腕部相机、MoveIt、桌面模型检查、行为节点和只有“复位/暂停”的面板。
已运行的底层驱动/相机/MoveIt 会复用；已有 armie/ghost_game 行为节点时拒绝并行启动。

只接已有硬件栈：

```bash
ros2 launch cyberdog cyberdog.launch.py motion_backend:=trajectory motion_enabled:=true senses_backend:=camera
```

纯模拟（不连接真机；另开相同 ROS_DOMAIN_ID 的终端调用服务）：

```bash

ROS_DOMAIN_ID=187 ros2 service call /cyberdog/reset std_srvs/srv/Trigger '{}'
```

## 核心行为

1. 复位：取消本节点当前动作，等待停止，位置控制平滑回到指定姿态并保持。
   不使用旧姿态标定文件覆盖复位值；不主动张爪丢掉已握住的物体。
2. 握手：待机时只监视 J3。位置相对复位目标误差 ≥0.03 rad 或静态力矩基线变化 ≥1 Nm，
   持续 0.25 s 后触发；等手臂静止、控制器允许动作后，先单独抬 J4 0.40 rad，再用 J6 向一侧歪头一次。
   然后通过 JTC 到握手姿态 `[-1.5707, 0.6, 0.8, 0, 0, 0]`，确认到位、稳定后切入阻尼。
   阻尼下移动关节触发夹爪收至 0.7 的功能当前关闭，可通过 `handshake_gripper_enabled` 恢复。
   触碰意图保留 6 s，不能切换时不强制运动。`touch_signal` 可选 position/torque/either。
3. 毛线球：待机或阻尼握手时使用 YOLOE 持续识别已指定的毛线球，一旦看到且控制器允许切换，
   就地开始位置伺服追踪。转换期间出现的球在到位后继续处理，无手势选择或额外 1 s 检测等待。
   RGB-D+对应时间 TF 将球心转到 base_link，球心经三帧中值去抖，在 40 mm 范围累计稳定 1 s 且有新鲜有效定位才开始抓取。
   锁定球心后，将必要的侧向对准、靠近、预抓取、抵达抓取点合成一次连续前伸，再闭爪 → 直接 JTC 到指定六关节放球姿态 → 停稳后张爪。
   本轮不再依据后续视觉改变或取消动作；规划失败时停稳后重新定位，最多尝试 3 次。点击复位再开始。
   流程完成仅代表动作完成，不声称实物已抓稳或已准确放置。

`/cyberdog/state` 发布状态，`/cyberdog/tracking_status` 发布触碰误差/静止计时/定位拒绝原因。
服务 `/cyberdog/reset`、`/cyberdog/stop`；同名命令可发到 `/cyberdog/command`。

## 实机配置与验证范围

`config/cyberdog.yaml` 是所有行为参数的入口。模型 FK 检查中，默认抬臂使名义 TCP 从约 0.218 m 升到 0.451 m。
J4 抬腕、J6 歪头幅度、J2/J3 最终姿态和 J3 触碰阈值为初值，
需结合当前实机方向、负载和空间调试。延用现有位置/阻尼控制器及限幅，不修改电机模式、标零或保护。
所有动作需要新鲜反馈、可确认的控制器状态和独占控制；前伸抓取还要求同步深度、TF、桌面碰撞模型和完整规划路径。
开始抓取前必须有新鲜、稳定的三维球心；本轮锁定后不再依赖视觉，前伸继续检查碰撞和完整路径；当前 JTC 放球模式没有独立抬球段。
当前放球段直接以 JTC 到用户确认过的示教关节姿态，不调用 MoveIt 碰撞规划；仍检查关节限位、速度、加速度、反馈、控制器和到位状态。
路径不完整时停止当前尝试，重新定位后再试。闭爪失败或人工暂停不会继续抬起。

当前仍使用原项目的名义 TCP 试验设置（尚未实物标定）和已记录桌面几何；现场改变时须更新桌面配置。
复制桌面参数不代表重新测量。之前原流程的直达抓取路径曾不完整；新包仍拒绝执行不完整路径。
本次只创建和测试代码，不自动替换正在运行的真机进程或执行机械臂运动。

## YOLOE 毛球检测（2026-10-31）

默认检测器已改为 `yoloe`，使用 `models/cyberdog-rope-yoloe.pt`。
它由 YOLOE-26s-seg 和这只实物球的一张参考图生成视觉提示，提示已经保存在权重中，
运行时不下载、不联网、不加载文本编码器。它不是“任意毛线球”通用训练模型。
原始网络 score 必须 ≥0.7；多个合格目标时不输出，丢失时不沿用旧框。
保留 150 ms 源图时间戳限期、深度/TF 验证和 1 s 静止判定，不修改运动参数。

当前开发容器已安装独立环境 `.cyberdog-yolo`，启动文件自动使用它运行 senses。
其他机器可在工作区执行（须先具备匹配 GPU 的 torch/torchvision 和 OpenCV）：

```bash
python3 -m venv --system-site-packages .cyberdog-yolo
.cyberdog-yolo/bin/python -m pip install --no-deps ultralytics==8.4.176
```

不升级系统 GPU 依赖。非默认环境可传 `senses_python:=/absolute/path/to/python`。
默认 GPU 参数 `ball_yolo_device: "0"`，配置中可改为 `cpu`，但应重新测量延迟。
回退原模板：`ros2 launch cyberdog bringup.launch.py ball_detector:=template`。
预览：`ros2 launch cyberdog bringup.launch.py preview:=true`。
启动文件的 `ball_detector` 参数优先于 YAML 中同名参数。

同一段 891 帧录像的原始 YOLOE 输出中，837 帧 score ≥0.7（93.9%）；
640×400 输入的调用耗时中位数 8.8 ms、P95 11.6 ms（不含首次加载）。
第一帧用于指定目标，其余帧不用于训练；这不是独立场景的 mAP 或真机闭环验收。
90 个无球区域裁剪未出现 ≥0.7 的输出，不能代表所有背景上的误检率。
普通 COCO YOLO11s 的 sports ball 在 30 帧抽样上无检测（阈值 0.1）。
权重来源、哈希与参考框见 `models/manifest.json`。
Ultralytics 代码和模型遵循其 AGPL-3.0/商业许可条款，不能沿用本包 Apache-2.0 声明。

## 跟踪范围与 1 秒抓取触发修复

左右（J5）相对开始追踪姿态默认允许 ±1.2 rad，原为 ±0.35；
上下（J4）默认 ±1.0 rad，原为 ±0.25。参数为
`ball_tracking_yaw_range` / `ball_tracking_pitch_range`。
图像伺服和轨迹输出两层使用同一组参数，保留机械关节限位、0.05 rad 边界余量及速度/加速度限制。
J1/J2/J3/J6 在图像跟踪阶段仍固定；前伸抓取由后续 MoveIt 路径完成。

旧实现会在每次无球观测或 TF ExtrapolationException 时直接清零稳定计时。
当前在 150 ms 源图有效期内等待对应时间戳的深度和 TF，非阻塞地重试，不使用最新 TF 替代。
开始抓取前，短暂漏检清除当前可抓取目标，但保留静止历史；恢复后必须再次满足同一空间锚点 40 mm 范围，
相邻有效 3-D 观测间隔超过 800 ms 则重新计时；在范围内恢复有效定位后，按实际间隔接续计时，不再把每个间隔截为 200 ms。
三帧中值滤波抑制孤立跳点，单帧深度拟合失败也按短暂漏检处理。球真正移动、当前无可靠深度或过期时不能开始抓取。
定位新鲜度按源图时间计算，队列等待不能延长目标寿命。
面板显示空间静止计时和等待原因；`/cyberdog/tracking_status` 增加 `target_valid`、`last_reason`、`dwell_sec`。
此处“1 秒”是球在世界坐标内稳定的时间，不是单纯停在图像中央的时间。
计时完成后仍要通过控制器、同步定位、碰撞与完整路径检查；不会强行执行不完整路径。

## 阻尼握手切回位置模式的底层修复

`mit_position_adapter_controller` 的接管逻辑已增加可行的阻尼增益过渡：
若立即启用目标 Kd 所需的启动前馈超出上限，而继承原 Kd 可以在上限内保持首帧力矩，
则先继承 Kd，再用已有 `gravity_compensation.transition_duration`（当前 1 秒）渐变到目标值。
不提高前馈力矩上限、不裁剪承载力矩、不改变最终位置增益。真实超限仍在写命令前拒绝。
正常可行的切换维持原行为。启动日志增加请求力矩、上限和瞬时速度，便于区分真实超限与增益切换影响。

可恢复的激活拒绝返回生命周期 FAILURE，保留 inactive 状态和导出的接口；
不再因这类拒绝进入 unconfigured，导致 STRICT 切换回滚时轨迹控制器接口消失。
控制器接口绑定错误仍按 ERROR 处理。

此修复位于工作区的 `zephyr_common/zephyr_controllers/mit_position_adapter_controller`，
不是只有 cyberdog Python 包。当前工作区已编译安装；跨机器部署需同时应用底层补丁并编译。
必须结束旧的完整 bringup（含 ros2_control_node），再重新运行 bringup.launch.py；
只重启行为节点或只按复位不能加载新的控制器共享库。

## 近距离抓取方向修复

现场只读采集复现：球心位于当前 TCP 前方约 92.5 mm，而旧算法始终把接近点放在
球心后方 100 mm，导致首段沿夹爪轴后退约 7.5 mm，并同时侧移。现在同时读取当前
TCP 的位置和姿态，接近点退距取 `min(100 mm, 球心轴向距离 × 0.6)`，
预抓取退距取接近退距的 0.7；三个接近阶段沿夹爪轴依次前进，最后到球心。
夹爪朝向保持不变，侧向移动补偿相机与 TCP 的偏置。球在夹爪后方或前向距离不足 5 mm 时，
仍拒绝生成抓取路径。轴向间隙足够但偏离夹爪轴超过 45 度时，先增加侧向对准段；近球采用下方说明的小范围直接修正。
没有改动名义 TCP 或相机安装外参。

现场彩色 CameraInfo 有非零八项畸变，D2C 深度 CameraInfo 的畸变为零；
两者同 frame_id、同 K，并不意味着像素坐标相同。定位现在读取两份 CameraInfo，
先将彩色检测区域去畸变，再映射到深度像素，使用深度自身的内参与畸变恢复三维点。
这修正了离轴目标的映射；本次靠近画面中心的回放中，该项修正的球心变化中位数为零，
确认此次反向动作的直接原因是固定 100 mm 退距。

`/cyberdog/tracking_status` 的 `ball.grasp_geometry` 记录球心、TCP、
球在 TCP 坐标中的位置、首段位移和完整路径（必要时包含对准段）。规划前日志也打印球心与首段位移，
单位 mm，TCP +Z 表示夹爪前方。停止原因区分定位失败、源数据过期和球心偏移量。
开始抓取前保留 1 秒静止要求、200 ms 定位新鲜度；稳定范围现为 40 mm，前伸的完整路径与碰撞检查均保留。

验证：80 项 Python 测试通过；76 个可比较的现场回放样本中，旧路径有 72 个首段后退，
新路径无首段后退。真实 MoveIt 对记录的球心和检查时的当前姿态返回完整路径
（fraction=1.0，161 点），只调用规划服务，没有执行。记录中仍有球面拟合拒绝，
不能用被拒绝的球心开始新尝试；锁定后的丢失处理见下节。尚未验证实物闭爪成功。

本节改动是 Python 代码，当前工作区安装已指向新源码；重启 cyberdog 行为进程后生效，
仅点击复位不会重新载入代码。

## 抓取中丢失与自动重试

默认启用 `grasp_blind_after_lock: true`。球在世界坐标稳定 1 秒后，冻结本轮球心和半径；
进入准备、规划或前伸后，即使 YOLO 漏检、深度拟合失败或图像过期，也继续朝已锁定的球心
执行通过碰撞检查的完整路径，包括到位闭爪、抬起、转向桌面、下降和张爪。不会因为一帧 `target unavailable` 直接暂停。
这表示遮挡期间按最后确认的位置抓取，不表示仍能观察到球。

当前默认策略在锁定后不再处理新的球心定位，视觉丢失、偏移、深度拟合失败均不会打断本轮动作。
即使球后来真的移动，也仍朝原锁定位置完成本轮尝试。
仅在关闭 `grasp_blind_after_lock` 时，恢复原来的视觉监视：新鲜三维观测离开锁定位置 ≥10 mm
会取消并重新追踪；该移动证据不能被后续漏检清除。

自动恢复适用于规划服务暂不可用、路径不完整、规划超时、
接近几何不合适、规划期间机械臂位置改变，以及轨迹目标被明确拒绝。
取消旧动作后，等待动作结果、关节静止和控制器允许，再以当前姿态重新跟踪，重新累计 1 秒并重新规划。
每轮默认最多 3 次尝试（包含第一次），失败间隔至少 1 秒；本轮抓取和放置的总时限为 120 秒。
次数不会在重新追踪时清零；点击复位开始新的轮次。达到次数上限后暂停。
关节反馈失效、跟随误差、控制器异常、结果不确定或闭爪失败仍暂停，不自动张爪重来。
人工暂停会取消等待中的重试和迟到回调；无法确认上次动作停止时不会启动下一次。

配置项（重启行为节点后生效）：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `grasp_blind_after_lock` | `true` | 锁定后按固定位置执行，本轮不再依赖视觉 |
| `grasp_continue_on_loss` | `true` | 关闭盲伸模式时，视觉丢失是否仍继续本轮抓取 |
| `grasp_max_attempts` | `3` | 每轮总尝试次数，包含第一次 |
| `grasp_retry_delay_sec` | `1.0` | 自动重新定位前的最短等待 |
| `grasp_attempt_timeout_sec` | `120.0` | 单次抓取从锁定开始的总时限 |

面板和 `/cyberdog/tracking_status` 显示尝试次数、是否使用锁定位置、是否等待重试。
同时设置 `grasp_blind_after_lock: false`、`grasp_continue_on_loss: false`，可恢复丢失即取消本次尝试。

验证：95 项 Python 测试通过，包含准备阶段丢失、各前伸阶段丢失仍完成闭爪/抬起、
真实规划分支使用冻结半径、三次重试与次数上限、重新累计稳定时间、
迟到的动作接收/完成回调、人工暂停以及控制器反馈丢失。独立 ROS_DOMAIN_ID=188 的
模拟 launch 完成完整流程；测试域 187 和模拟域 188 均与真机隔离。本次没有执行真机抓取。

## J3 触发后的打量动作与阻尼收爪

J3 触发后按顺序执行三个位置 JTC 动作，每段到位并验证反馈后才执行下一段：

1. 捕获当前六关节姿态，只将 J4 增加 0.40 rad（约 22.9°）；其余关节保持当时的位置。
2. 保持 J4 抬腕，用 J6 相对开始姿态向一侧歪 0.25 rad，停留 0.08 秒。

## 零位附近反馈导致抬腕中断的修复

`joint2 measured position -0.000383 outside [0.000000, 3.140000] rad`

现在捕获动作起点时允许最多 0.002 rad（约 0.115°）的边界误差，

处理覆盖打量姿态生成、`Robot.move()` 预检查，以及异步查询控制器后真正提交 JTC 轨迹的检查。
提交时仍使用稳定的 JTC 参考作为起点；控制器接管时若参考也携带同样的微小越界，按同一范围处理。
原始关节反馈保持不变，继续用于静止判定、J3 触碰和到位验证。
显式目标角度和所有发送轨迹点仍严格遵守原限位；超过 0.002 rad 的起点越界仍会停止。
复位目标仍为 `[-1.5707, 0, 0, 0, 0, 0]`，不修改标零、电机限位或运动速度。

新增边界回归覆盖六轴上下限、非法反馈、异步阶段的新反馈、严格目标限位，
以及携带同样 J2 误差的 ROS 假控制器完整握手流程。测试使用隔离域 187，没有执行真机动作。

## 毛球居中仍因 45 度检查反复重试的修复

相机图像中心不等于夹爪 TCP 的前向轴线。此前的现场记录中，球的图像归一化位置
仅为 `[-0.0148, -0.0096]`，但在 TCP 下的位置为 `[-38.4, 11.6, 32.7]` mm，
相对夹爪前向偏角 50.8°。旧逻辑把超过 45° 当作几何失败，重新图像追踪后仍可能遇到相同失败。

对这种位于夹爪前方、轴向间隙足够的偏侧球心，先生成对准和前伸路径：

1. `align`：保持当前夹爪朝向和 TCP 轴向位置，只沿 TCP 的 X/Y 方向移到球心轴线上。
2. `approach` → `pregrasp` → `grasp`：沿夹爪前向接近球心，抵达抓取点后才闭爪。
3. 当前 JTC 放球模式：闭爪成功后直接到指定放球位。旧 Cartesian 模式仍包含 `lift` 抬起 12 cm。

对准段不消耗轴向间隙；球心的前向距离必须仍大于球半径加 10 mm。
球在后方或前向距离不足 5 mm 时继续拒绝；近球半径条件的修正见下方更新。没有额外对准需要的普通距离前伸包含 approach、pregrasp、grasp 三个路径点。
包括新增对准段在内的完整路径，必须先通过 MoveIt 碰撞、完整率、关节限位和速度/加速度检查；
闭爪前的所有路径点从新鲜关节状态一次规划、一次执行；当前模式的预检查和执行均不包含抬球。
对准过程中不再用视觉打断本轮锁定位置，人工暂停仍取消；最多三次尝试的规则不变。

日志增加球心相对 TCP 的偏角和路径策略；对准现在包含在连续的 `grasp_approach` 中。
`grasp_geometry` 增加 `axis_angle_deg`、`first_stage`，几何拒绝也记录相对位置和原因。

验证使用此前采集的五个被 45° 检查拒绝的场景，在隔离域 188、禁用轨迹执行的 MoveIt 中，
五组完整路径均为 100%，且均通过现有指令限位检查。起始关节由记录的 TCP 位姿逆解恢复，
属于记录回放和模型验证，不等同于本次真机复测；当前未采集到新的真机话题。
全套 151 项 Python 测试通过，包含 11 项新增对准回归。重启当前 cyberdog launch 后生效，
当前 JTC 模式下，复位后静止持球可观察 `grasp_approach` → `grasp_closing` → `grasp_place`。

## 阶段音效

使用已合并的 [音频 PR #2](https://github.com/xiayip/cyberdog/pull/2) 中 23 个 WAV，
按 `audio/验证记录.json`、`audio/映射清单.json` 校验文件名、SHA-256、时长和 48 kHz/单声道/16 位 PCM 格式。
安装时音频和清单一起放入 `share/cyberdog/audio`。

| 行为 | 音效及触发方式 |
| --- | --- |
| 启动 / 刚回到待机 / 持续待机 | A1 / A2 / A3；A3 每 30 秒一次 |
| J3 触碰 | B1；待机至少 20 秒后改用 W1，60–300 秒用 W2，超过 300 秒用 W3，不叠加 B1 |
| J4 抬腕、最后抬起 / J6 歪头 | B3 / B2；歪头到位停留不重复播放 B2 |
| 阻尼中晃动关节 / 握手闭爪完成 | B4（最短间隔 4 秒）/ B5 |
| 发现球 / 开始追踪 / 丢失至少 0.5 秒后找回 | C1 / C2 / C3（最短间隔 4 秒）|
| 首次锁定、蓄势 | C4 静音，并停止追踪音 |
| 闭爪 / 抓放流程完成 | C5 / C6；C6 是动作完成反馈，不额外声称检测到抓牢 |
| 首次失败 / 再次失败 / 次数用尽 | D1 / D2 / D3 |
| 重试锁定新球心 | D4；替代此时的 C4 静音事件 |
| 点击复位 / 等待停止 / 开始回家 | E4 / E1 / E2 |
| 手动暂停、故障或退出 | E3：立即停止当前音频并清空队列 |
| 放球途中被拿走球，开始低头 | 复用 D3 委屈音 |

B4 独立检测阻尼中的关节运动，关闭自动握手闭爪时仍能发声；B5 仅在开启该闭爪功能且完成后播放。
首次看见球不会误报找回；锁定进入抓取后不再因视觉丢失/重现播放 C3。

行为节点只发布 `/cyberdog/audio_event`，独立的 `cyberdog_audio` 节点使用 `paplay` 播放。
声音不延长动作，也不等待音频完成。单进程串行播放、队列最多 4 条，超过 3 秒的待播事件丢弃；
暂停、复位、球锁定等切换可清除旧音频，停止后等待旧播放进程退出才启动新片段。
重复事件会被去重，音频文件/设备故障只记录告警，不停止机械臂。
`/cyberdog/audio_status` 给出播放器可用性、当前事件和错误信息。

```bash
# 默认开启音效；关闭本次 launch 的播放器：
ros2 launch cyberdog bringup.launch.py audio:=false
```

`cyberdog_audio.ros__parameters` 中可设置 `audio_volume`（0–1，默认 0.7）、
`audio_device`（空字符串跟随默认输出）、`audio_server`；修改后重启 launch。
在直接连接桌面音频的环境，`audio_server` 留空即可使用本机默认服务。
